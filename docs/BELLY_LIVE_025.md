# 025 — Live Belly Apply (experiment 32)

Requires patch 024. Analyze the mod, set Glutes/Hips/Thighs/Calves and all other production options in the main GUI, then choose Experiments > 32_belly_live_apply.py. The runner passes a private JSON snapshot of the actual controls (including unsaved slider changes and Wardrobe roles). No saved configuration is changed.

The production preview is evaluated once on a disposable copy. Belly is the only added field, using the existing RegionalControls and FieldComposer. The left viewport is the computed production baseline, not necessarily the current on-disk mod. Both cameras are linked; the right mesh updates after a short debounce when controls change. Full Body is default, and Skin only filters the display, not the deformation. Focus abdomen gives a side close-up. The field respects the existing mobility, seam and arm protections and garment distance fade; it does not fill holes in Skin or solve garment collisions. Open torso cuts may use the engine waist fallback. All controls are neutral at startup (depth=0). Depth is a normalized amplitude, Width/Height are field extents, Offset is relative to the groin-knee span.

Apply to mod explicitly confirms writing the accepted float32 geometry and Vector.buf. Original shading retains baseline frames; Adaptive/Geometric transport the baseline frames through the extra Belly displacement, and Legacy uses Adaptive transport for this extra field. Backups are created only on first apply (from the current buffers if no originals exist) and never overwritten. An incomplete backup pair is rejected. Current position/index/vector and original backup hashes must match the session snapshot. Writes are staged in the Meshes directory and ordinary replacement failures roll back. Two separate file replacements are not an atomic transaction against a process crash or power failure; close the game and other writers first. Do not force-kill the experiment during Apply. Restore in the main tool restores the original pair. The GUI refreshes Current on successful experiment completion. Repeated applies in one session always use the same baseline, not accumulated Belly. No configuration or INI is persisted by the experiment. Normal production Apply can overwrite the experimental result, and the Belly settings are not restored on reopening. This is not production integration.

The new after_shading observer exposes the baseline packed vectors without changing the production geometry/shading formulas. No new dependencies. Qt/PyVista rendering must be tested on Windows. The current validator checks newly reversed/near-degenerate faces, not visual curvature, all collisions or animation.
