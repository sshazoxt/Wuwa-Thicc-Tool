# 010 — Anatomical recovery and Force analyze transaction

Apply over 009. No new dependencies. Original eight detector weights, order and deformation code are unchanged.

ARF now checks lower Skin coverage plus upper skeleton branches when global vertex bone IDs are available. For missing upper branches, it creates a temporary anatomical hypothesis including eligible inactive alternatives, reads the engine's own bone labels, and validates the proposed group by reconstructing the engine skeleton. The default Full Body viewer assembly remains unchanged. Positive Naming, existing role eligibility, topology veto, unknown INI guards and explicit role protection still apply. Head/neck bridge candidates are considered with central, high, close geometry; neck is not a separate required engine seed. Local bone namespaces retain the previous spatial recovery behavior. The upper coverage flags represent branch/seed evidence, not independent hand mesh recognition. Final readiness remains subject to the original engine checks.

Force analyze bypasses saved role/anatomy lists without changing the JSON. It preserves other options, including manual landmarks. If a saved configuration differs, a dialog shows role and Anatomy differences; closing or rejecting it leaves the saved configuration and effective snapshot untouched. Acceptance writes the role/anatomy lists atomically and stores the completed analysis under the accepted configuration hash when cacheable. Preview/Apply does not request a second diagnostic if the accepted result is ready. Incomplete results still show warnings and remain blocked. The normal deformation operation still computes the necessary geometry. The detector cache can be refreshed even if a proposal is rejected. Full Body remains virtual.

Tests: four existing tests plus three headless tests for proposal commit/cache reuse, changed-config protection, and inactive-arm recovery with a mocked skeleton. Actual mod buffers and Windows GUI behavior are not tested here.
